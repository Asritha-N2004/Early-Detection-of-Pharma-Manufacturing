# Data dictionary and relational provenance

Measurement fields are `process`, `batch`, `equipment`, timezone-aware `timestamp`, registry `parameter`, numeric finite `value` or null quality event, exact `unit`, `source` (`synthetic`, `uploaded`, `rest`), `stage`, optional binary `label`, supplied `low`/`high` and `quality`. Uploaded ranges do not override configured operating limits. Physical bounds, alert thresholds and critical-parameter flags are configurable. Original accepted and quarantined payloads remain preserved.

Accepted sensor identity hashes process/batch/equipment/UTC timestamp/parameter. Duplicate submissions create quality events rather than duplicate sensor rows. Missing values, unknown parameters, unit mismatches, physically invalid measurements and communication gaps remain traceable. Gap policy is configurable. Invalid request schemas are rejected without echoing passwords in validation responses. Batch and equipment must be selected when an analysis would otherwise mix identities.

The seed-42 generator creates 15,702 synthetic observations across four processes and six chronological batches each. It includes nominal one-minute sampling, deliberately omitted communication periods, missing values, duplicates, noise, batch variability, gradual drift and spikes. Labels indicate synthetic excursions, never confirmed real deviations. `scripts/explore_data.py` produces a JSON profile and a four-process figure under `data/processed`.

Relational tables include `users`, `roles`, `permissions`, `role_permissions`, `user_roles`, `user_sessions`, `manufacturing_processes`, `process_parameters`, `equipment`, `equipment_events`, `batches`, `sensor_readings`, `reading_contexts`, `data_quality_events`, `anomaly_events`, `predictions`, `deviation_records`, `root_cause_hypotheses`, `risk_assessments`, `agent_workflows`, `agent_execution_logs`, `investigation_records`, `human_reviews`, `model_registry`, `model_evaluations`, `generated_reports`, `audit_logs`, `system_configurations`, `workflow_jobs`, and canonical `analytical_records`. Alembic adds its version table.

`reading_contexts` connects original sensor rows to normalized batch/equipment/parameter foreign keys without destructive changes to historical source columns. Typed analytical indexes reference preserved canonical evidence documents. Deviations link to workflows; hypotheses and investigations link to deviations; model evaluations link to model versions. Existing records are backfilled by migrations. Locally inspected schema: 31 tables including Alembic, with 35 foreign-key links.

Durable LangGraph state additionally uses `workflow_checkpoints`, `workflow_checkpoint_writes` and `workflow_execution_journal`, in a separate sibling SQLite store locally or separate PostgreSQL tables. Back up both stores and model artifacts together during a writer maintenance window.
